# UI/UX README — Élise

## Scope

This document summarizes the frontend UI/UX implementation of the project. It documents the UI features that are currently implemented, including the interface, accessibility, internationalization, reusable components, and known limitations. This document was initially generated by ChatGPT and then manually reviewed and edited.

## Responsive Interface

The interface is built with React, TypeScript, Tailwind CSS, and responsive flex/grid layouts that adapt to the viewport.

Features currently implemented:

* navigation and main pages accessible on both desktop and mobile
* panels and cards that reorganize themselves according to the available screen width
* game and editor areas that use scrolling when space is limited
* compact language selector, usable on small screens as well
* dedicated touch layout for the game screens: a square play area sized to the screen, the map leaderboard filling the remaining space, and an on-screen joystick anchored bottom-right in both orientations
* a tighter camera on touch devices, so tiles stay large enough to read on a phone

Current limitation:

* some content-heavy pages, especially the editor, remain more comfortable to use on large displays than on small mobile devices

## Accessibility

Current accessibility foundation:

* use of standard HTML components for buttons, forms, modals, and links
* keyboard navigation expected across forms and interactive menus
* translated text to improve multilingual usability
* visual contrast designed around a dark color palette with readable accent colors

Known limitations:

* no complete accessibility audit is documented in the repository
* screen reader validation is not formally included in the test suite
* some highly dense areas of the game and editor still require manual keyboard-only verification

## Design System

The application relies on a lightweight design system centralized in the codebase, without an external tool such as Storybook.

Visual foundations:

* dark theme with surfaces, borders, and gold/silver accents
* rounded components, subtle shadows, and consistent visual hierarchy
* shared styles implemented with Tailwind CSS and a few common utility classes

## Internationalization

Internationalization is managed with `react-i18next` and `i18next-browser-languagedetector`.

Current configuration:

* resources loaded for the `common` and `legal` namespaces
* automatic browser language detection
* French configured as the fallback language
* language switching available through the `LanguageSelector`

## Supported Languages

Languages currently available in the application:

* French (`fr`)
* English (`en`)
* Dutch (`nl`)

Fallback behavior:

* if the detected language is not supported, the application falls back to French

## Notifications

The project does not include a dedicated notification center.

Current implementation:

* user notifications are handled exclusively through toast notifications
* `ToastProvider` is mounted at the root of the application
* `ToastContainer` is rendered only once at the global level
* pages use `showToast()` for temporary feedback such as success, error, and informational messages

Conclusion:

* for this project, toast notifications are the only UI notification mechanism

## Known UI/UX Limitations

Current acknowledged limitations:

* the experience remains more robust on desktop than on small mobile screens for dense views
* the design system is centralized in the codebase but is not supported by an external visual component catalog
* notifications are intentionally simple, with no persistent notification center
* a complete accessibility audit is still required if comprehensive compliance is a goal
